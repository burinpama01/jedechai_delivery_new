1. P0 — แก้ secret ที่หลุดไปกับแอปก่อนเริ่มงาน

พบระหว่างวิเคราะห์ (ยืนยันแล้ว 2026-09-19) jedechai_delivery_new/pubspec.yaml ประกาศ .env เป็น Flutter asset → ไฟล์ถูก bundle เข้าแอป ตรวจ build/app/outputs/bundle/release/app-release.aab พบ base/assets/flutter_assets/.env ซึ่งมีตัวแปร SUPABASE_SERVICE_KEY, SUPABASE_DATABASE_URL, FIREBASE_PRIVATE_KEY, OMISE_SECRET_KEY, PAYMENT_SECRET_KEY ฯลฯ ใครแตก APK/AAB ก็ได้สิทธิ์เต็มฐานข้อมูลและระบบชำระเงิน ถ้าเพิ่ม OPENAI_API_KEY ในไฟล์เดียวกันแล้ว build ใหม่ คีย์ OpenAI จะหลุดด้วย (build ล่าสุดยังไม่มีคีย์นี้)

งานที่ต้องทำก่อนเริ่ม AI Quick Setup (ต้องให้ผู้ใช้อนุมัติทุกข้อ เพราะกระทบ production):

  1. อย่าอัปโหลด AAB 1.10.1+118 ตัวปัจจุบัน ขึ้น Play Store
  2. แยกไฟล์: .env.client (เฉพาะ SUPABASE_URL, SUPABASE_ANON_KEY, GOOGLE_MAPS_API_KEY แบบจำกัด package/SHA) เป็น asset ส่วน secret ที่เหลืออยู่ในไฟล์ที่ไม่ bundle
  3. ย้าย secret ฝั่ง server ไป supabase secrets set (รวม OPENAI_API_KEY)
  4. ย้ายการเรียก Omise ที่ใช้ secret ออกจากแอป — lib/common/services/omise_service.dart (บรรทัด ~91, ~135) อ่าน EnvConfig.omiseSecretKey ฝั่ง client อยู่จริง ต้องทำ Edge Function แทนก่อน ไม่งั้นพอ rotate แล้วการชำระเงินจะพัง (supabaseServiceKey มี getter ใน supabase_config.dart แต่ไม่พบจุดเรียกใช้ — ลบทิ้งได้)
  5. Rotate ทุก key ที่เคยหลุด: service role / JWT secret, รหัส DB, Firebase service account, Omise secret, Vercel token, Resend, SMS — เพราะแอปเวอร์ชันเก่าที่อยู่บนเครื่องผู้ใช้ยังมี key เดิม
  6. เพิ่ม check ใน build script: fail ถ้า asset มีคำว่า SERVICE, SECRET, PRIVATE_KEY, DATABASE_URL

2. เป้าหมายและหลักการ

ข้อความหลัก: “มีแค่รูปเมนู ก็เปิดร้านบน JDC ได้” — สมัคร → เลือกแพ็กเกจ → ถ่ายรูปเมนู → ตรวจ → ส่งเปิดร้าน ภายในครั้งเดียวโดยแอดมินแค่กดอนุมัติ

หลักการที่คงไว้จาก v0.1:

  • Draft-first — AI ไม่เขียนลง menu_* ตรง ๆ ทุกอย่างผ่านตาราง import แล้ว Publish ผ่าน RPC
  • ห้าม AI เลือกเองเมื่อข้อมูลขัดกัน (ราคาต่างกันระหว่างรูป, logo) ร้านต้องเลือก
  • Server derive ตัวตนร้าน จาก JWT (auth.uid() = profiles.id) ไม่เชื่อ merchant_id ที่ client ส่ง
  • ไม่มี secret ใน Flutter — OpenAI เรียกจาก Edge Function เท่านั้น
  • ห้าม AI เติมข้อเท็จจริง (Organic, 100% Arabica) ที่ไม่มีในเมนู

4. ร้านเลือกแพ็กเกจ GP เอง ใหม่ใน v2

4.1 แพ็กเกจตามโปสเตอร์

ร้านเลือกได้ว่าจะให้ JDC หัก GP มากขึ้นเพื่อแลกกับค่าส่งที่ถูกลงสำหรับลูกค้า (ยิ่ง GP สูง ค่าส่งยิ่งถูก ลูกค้ายิ่งสั่งง่าย)

รูปแบบที่ 1

หัก 15%
  • ค่าส่ง 10 ฿ ในระยะ 5 กม. จากร้าน
  • เกินระยะคิด 3 ฿/กม.
  • เหมาะ: ร้านที่อยากเก็บกำไรต่อจานสูง

รูปแบบที่ 2

หัก 20%
  • ค่าส่ง 5 ฿ ในระยะ 7 กม. จากร้าน
  • เกินระยะคิด 2 ฿/กม.
  • เหมาะ: ร้านทั่วไป สมดุล

รูปแบบที่ 3

หัก 25%
  • ค่าส่ง 0 ฿ (ส่งฟรี) ในระยะ 10 กม.
  • เกินระยะคิด 1 ฿/กม.
  • เหมาะ: ร้านที่อยากได้ยอดขายและลูกค้าไกล
ตัวอย่างคำนวณ (ให้ใส่ในหน้าเลือกแพ็กเกจของแอปด้วย)
แพ็กเกจร้านได้รับลูกค้าจ่ายค่าส่ง

ค่าส่ง = ค่าเริ่มต้น + (ระยะเกิน × ฿/กม.) — ตัวอย่างนี้คิดระยะเกินเป็นทศนิยมตรง ๆ ส่วนการปัดเศษจริงให้ยึดสูตรใน merchant_food_config_service.dart / checkout ไม่รวมส่วนลดหรือโปรโมชัน

6. Architecture (OpenAI)

Flutter (merchant)
  │ 1. ย่อรูป ≤ 2048px, JPEG q≈80, auto-rotate EXIF
  │ 2. upload → Storage bucket "merchant-imports" (private, path = {uid}/{job_id}/n.jpg)
  │ 3. supabase.functions.invoke('merchant-ai-menu-import', {job_id, mode})   ← JWT
  │    mode = 'onboarding' | 'append'  (append = ร้านเดิมเพิ่มเมนู, v4)
  ▼
Edge fn: merchant-ai-menu-import         (ตอบกลับทันที 202 + job_id)
  │ - verify JWT, role = merchant, ownership ของ path ใน storage
  │ - rate limit / quota (ai_import_quota)
  │ - job.status = 'queued'
  ▼
Worker: merchant-ai-menu-worker          (EdgeRuntime.waitUntil หรือ pg_cron ทุกนาที แบบ claim-pattern
  │                                        เหมือน notify-admin-events)
  │ - signed URL ของรูป (อายุสั้น) → OpenAI Responses API
  │   · input: image(s) + system prompt ภาษาไทย
  │   · (append) แนบรายชื่อหมวดเดิมของร้าน เพื่อให้ AI เลือกหมวดที่มีอยู่ก่อน

6.1 การตั้งค่า OpenAI

  • คีย์: supabase secrets set OPENAI_API_KEY=… (อ่านด้วย Deno.env.get) — ห้ามอยู่ใน .env ของ Flutter (ดูข้อ 1)

8. AI Output Schema + Confidence

{
  "items": [{
    "category": "กาแฟ",
    "name": "ชาเขียว",
    "description": null,
    "variants": [ {"label":"เย็น","price":55}, {"label":"ปั่น","price":65} ],
    "base_price": 55,
    "addons": [ {"group":"ท็อปปิ้ง","label":"ไข่มุก","price_delta":10} ],
    "confidence": {"name":0.98,"price":0.93,"category":0.9},
    "price_text_raw": "เย็น 55 / ปั่น 65"
  }],
  "unreadable_regions": ["มุมขวาล่าง เลือนราง"],
  "logo_detected": false
}
  • ให้ AI ส่ง price_text_raw (ข้อความราคาตามที่เห็น) เพื่อให้ server ตรวจซ้ำว่าตัวเลขตรงกับ price
  • Confidence สุดท้าย = ค่าจาก AI ปรับด้วยกฎฝั่ง server (ไม่เชื่อค่า AI อย่างเดียว):
    • ราคาไม่ใช่จำนวนเต็ม / < 5 ฿ / > 2,000 ฿ / ไม่ตรงกับ price_text_raw → ลด price เป็น ≤ 0.6
    • variant ไม่เรียงราคา หรือ base_price ≠ ราคาต่ำสุด → ติด issue
    • ราคาขัดกันระหว่างรูป → price_conflict บังคับให้ร้านเลือก (ห้าม auto)
  • เกณฑ์: ราคา ≥ 0.95 ปกติ / 0.80–0.94 แนะนำตรวจ / < 0.80 ต้องตรวจ · ชื่อ/หมวด ≥ 0.90 / 0.70–0.89 / < 0.70
  • Duplicate: normalize ชื่อ (ตัดช่องว่าง, lowercase, ตัดคำ “เมนู”) + ราคาเท่ากัน → merge; ชื่อตรงแต่ราคาต่าง → conflict; ตรวจกับเมนูเดิมของร้านด้วย — กติกาเต็มอยู่ใน ข้อ 10.3 (D4 ปิดแล้ว)

9. Review / Publish

  • หัวสรุป: พบ 32 รายการ · ✓ พร้อม 25 · ⚠️ ต้องตรวจ 5 · ❌ อ่านไม่ได้ 2 + filter (ทั้งหมด/ต้องตรวจ/พร้อม/แก้แล้ว/ไม่ใช้)
  • การ์ดรายการ: ชื่อ ราคา หมวด ตัวเลือก + badge confidence + ปุ่ม [แก้ไข] [ไม่ใช้] + ปุ่ม “ดูรูปต้นทาง” (V1 เปิดรูปทั้งหน้า ยังไม่ทำ bounding box)
  • อนุมัติทั้งหมดที่พร้อม อยู่ใน V1 (ไม่ใช่ V1.1 ตามที่ v0.1 เขียนขัดกัน) — รายการที่มี issue ต้องแก้หรือกด “ยืนยัน” ทีละรายการ
  • Preview: แสดงหน้าร้านแบบที่ลูกค้าเห็น (reuse widget ของ restaurant_detail_screen) ก่อนกด Publish
  • Publish = RPC merchant_publish_import(p_job_id): lock job (FOR UPDATE), เช็ค owner + ทุกรายการไม่มี issue ค้าง, สร้างหมวด → option groups (dedupe) → items → links ใน transaction เดียว, เขียน published_menu_item_id + audit, idempotent (กดซ้ำไม่สร้างซ้ำ)
  • V1 = เพิ่มต่อท้าย เมนูเดิม ไม่ลบ/แทนที่ (D4 ตัดสินแล้ว) — ใช้กับทั้งร้านใหม่และร้านเก่า
  • Error: “อ่านไม่ได้บางส่วน” → [ถ่ายใหม่] [อัปโหลดเพิ่ม] [กรอกเอง] ไม่บังคับ retry AI

10.4 กติกาความปลอดภัยสำหรับร้านที่อนุมัติแล้ว

13. Definition of Done

GP self-service (Phase 1)

  • ร้าน food ใหม่เลือกแพ็กเกจเองได้ เห็นตัวอย่างคำนวณ และติ๊กยอมรับเงื่อนไข
  • แอดมินอนุมัติร้านได้โดยไม่ต้องกรอก GP; ร้าน food ที่ไม่มีแพลนอนุมัติไม่ได้ (ยกเว้น override พร้อม audit)
  • มี history การเลือก/เปลี่ยนแพลนพร้อม snapshot ค่า
  • ออเดอร์แรกของร้านใหม่คิด GP และค่าส่งตรงกับแพลน (ทดสอบ 3 แพลน × ระยะในเกณฑ์/เกินเกณฑ์)

AI Menu Import V1 (Phase 2)

  • อัปโหลดได้ 1–8 รูป, ประมวลผลแบบ async, เห็นสถานะ realtime
  • Golden set: ราคาถูกต้อง ≥ 95% ของรายการที่อ่านได้, ชื่อ ≥ 90%, ไม่มีรายการราคาผิดที่ติดสถานะ “พร้อม” (false-ready = 0 ใน golden set)
  • Variant/add-on แปลงเป็น option group ถูกต้องตาม schema จริง, group ซ้ำถูก dedupe
  • แก้ / ไม่ใช้ / อนุมัติทั้งหมดที่พร้อม / เลือกราคาเมื่อขัดกันได้
  • Preview ก่อน Publish; Publish atomic และ idempotent
  • มี ai_runs และ audit ครบ; โควตาทำงาน
  • ไม่มี secret ใดใน Flutter asset (มี build check)
  • ผ่าน code_reviewer + policy test + smoke test

ร้านเก่าเพิ่มเมนูด้วย AI (Phase 2, v4)

  • ร้าน approved เข้า “เพิ่มเมนูด้วย AI” จากหน้าจัดการเมนูได้ และเมนูใหม่ต่อท้ายเมนูเดิมถูกหมวด
  • รายการที่มีอยู่แล้วถูกติด “มีอยู่แล้ว/ราคาเปลี่ยน/คล้าย” ถูกต้องใน golden set 5 เคส และไม่มีเมนูซ้ำหลุดเข้าไป
  • Publish โหมด append ไม่แก้/ลบเมนู หมวด หรือ option group เดิม (ตรวจด้วย test ก่อน/หลัง)
  • เลือกซ่อน/เปิดขายตอน Publish ได้ และ “ซ่อนเมนูชุดนี้ทั้งหมด” ซ่อนเฉพาะรายการของ job นั้น
  • แอดมินได้รับแจ้งและดูประวัติ import ของร้านได้

15. ความเสี่ยง

  • ราคาอ่านผิดแล้วหลุดขึ้นขาย — ความเสี่ยงสูงสุด: ลดด้วยเกณฑ์ราคาเข้มกว่า, price_text_raw cross-check, Preview บังคับ, และแอดมินยังเป็นด่านสุดท้ายตอนอนุมัติร้าน
  • v4 ร้าน approved ไม่มีแอดมินกั้นก่อนขึ้นขาย — ราคาผิดถึงลูกค้าทันที: insert-only, Preview + ติ๊กยืนยันบังคับ, ค่าเริ่มต้นซ่อนไว้ก่อน (D8), ซ่อนทั้งชุดย้อนหลัง, แจ้งแอดมิน
  • v4 เมนูซ้ำ/หมวดกระจัดกระจายในร้านเดิม — จับคู่หมวดเดิมก่อน, หมวดใหม่ต้องยืนยัน, ตรวจซ้ำรวมรายการที่ซ่อน และ re-check ตอน publish
  • ต้นทุน AI บานปลาย — ย่อรูปฝั่ง client, โควตา, ai_runs + แจ้งเตือน
  • Edge Function timeout / memory — async worker, ≤ 2 รูปต่อ request, claim-pattern + retry
  • ตัวเลข confidence จาก LLM ไม่ calibrate — วัดกับ golden set แล้วปรับเกณฑ์ก่อนเปิดจริง
  • เงื่อนไข GP ที่ร้านเลือกเองเป็นข้อผูกพันทางการเงิน — ต้องมีหลักฐานการยอมรับ (G4) และข้อความเงื่อนไขที่ตรวจโดยเจ้าของธุรกิจ
  • Secret หลุดใน build เก่า — rotate แล้วแอปเก่าที่ใช้ service key (ถ้ามีจุดใดใช้) จะพัง ต้องตรวจก่อนว่าโค้ด Flutter อ่าน secret ตัวใดจริงบ้าง
