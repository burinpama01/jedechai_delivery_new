ทีมแอดมิน — แผนลงมือ P1

อ้างอิงแบบ Plan/Admin_Staff_Permissions_Design_v1.html · 2026-10-09 · สถานะ: กำลังทำ

เป้าหมาย P1: superadmin สร้าง/จัดการทีมและสิทธิ์ได้, staff ล็อกอิน admin-web ได้และเห็นเฉพาะเมนูที่มีสิทธิ์, ทุก action ของ staff ผ่านประตูสิทธิ์ใน admin-actions (อนุญาต / ห้าม / ส่งขออนุมัติ), ผู้อนุมัติพิจารณาคำขอได้, มี audit log · ยังไม่เปิด policy อ่านตารางให้ staff (P2)

1. ฐานข้อมูล — supabase/migrations/20261009100000_admin_staff_p1.sql

  • profiles_role_check เพิ่ม staff · trigger กันลด superadmin จนเหลือ 0 คน
  • ตาราง: admin_role_templates, admin_staff, admin_staff_page_overrides, admin_staff_action_overrides, admin_approval_requests, admin_audit_log · RLS: superadmin อ่าน/เขียนผ่าน RLS ไม่ได้ (เขียนผ่าน admin-actions เท่านั้น) อ่านได้ · staff อ่านแถวตัวเอง / คำขอที่ตัวเองขอหรืออนุมัติได้
  • ฟังก์ชัน: admin_staff_access(uuid) (service_role), my_admin_access() (ผู้ใช้ปัจจุบัน), staff_page_level(text), admin_approvers_for_page(text[]), admin_find_user_by_email(text) (service_role)
  • บทบาทตั้งต้น 5 บทบาท (is_system)

2. Edge function

  • _shared/admin-permissions.ts (pure): แคตตาล็อก action → หน้า/ชนิด (read/write/sensitive/super) + decideAccess() · ทดสอบด้วย node
  • _shared/admin-auth.ts: verifyAdminOrStaff() (ของเดิม verifyAdmin คงไว้ให้ function อื่น)
  • admin-actions: แยก switch เป็น runAction() · ประตูสิทธิ์ก่อนรัน · action ใหม่ team_add_existing, team_create_account, team_update, team_remove, superadmin_grant, superadmin_revoke, template_upsert, template_delete, approval_decide, approval_cancel · audit ทุก action · แจ้งผู้อนุมัติ (notifications + คิว Telegram/LINE)

3. admin-web

  • ล็อกอินรับ role staff ที่ active · โหลด my_admin_access() · ซ่อนเมนูที่ไม่มีสิทธิ์ · กันเปิดหน้าที่ไม่มีสิทธิ์
  • หน้าใหม่: คำขออนุมัติ (ทุกคนในทีม), ทีมแอดมิน และ บันทึกการทำงาน (superadmin)
  • callAdminAction รู้จักผล pending_approval

4. ลำดับ rollout

  1. ทดสอบ: unit (decideAccess/แคตตาล็อก), node --check, BEGIN/ROLLBACK บน prod (สิทธิ์ทุก tier, กันลด superadmin, RLS ตารางใหม่)
  2. code_reviewer
  3. apply migration (additive — admin-actions เดิมยังใช้ได้) → deploy admin-actions → deploy admin-web
  4. ทดสอบหลัง deploy: superadmin ทำงานเดิมได้ (เรียก action อ่านอย่างเดียว), staff ทดสอบ (ถ้าผู้ใช้ให้บัญชีทดสอบ)

5. นอกขอบเขต P1

policy อ่านตารางสำหรับ staff, ซ่อนปุ่มราย action ในแต่ละหน้า, RPC/การเขียนตรงของ admin-web (5 จุด) ให้ staff ใช้ได้ — ทั้งหมดอยู่ใน P2/P3 · ระหว่างนี้ staff เขียนตรง/RPC ไม่ได้เลย (deny by default)
