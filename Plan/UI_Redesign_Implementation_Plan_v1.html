3สถาปัตยกรรม token 3 ชั้น

หัวใจของการทำงานขนานคือ Wave 0 ต้องปิดจบก่อน แล้วหลังจากนั้นไม่มีใครแตะไฟล์ธีมอีก ทุกเอเจนต์แค่ "เรียกใช้" token

ชั้นไฟล์หน้าที่
1 — ค่าดิบlib/theme/jdc_palette.dartค่าสีตรงกับ CSS variable ในแคนวาส 1:1 แยก light / dark ห้ามมี logic

4กฎการทำงานหลายเอเจนต์

  1. File ownership แบบผูกขาด — แต่ละ task มีรายการไฟล์ของตัวเอง เอเจนต์แก้ได้เฉพาะไฟล์ในรายการนั้น ไฟล์นอกรายการห้ามแตะแม้แต่การจัด format
  2. ไฟล์ธีมล็อกหลัง Wave 0 — lib/theme/* ห้ามแก้โดยเอเจนต์ใน Wave 1+ ถ้าขาด token ให้ หยุดแล้วรายงาน ไม่ใช่เพิ่มเอง (กันชนกันและกันสร้าง token ซ้ำ)
  3. หนึ่ง task หนึ่ง worktree — spawn ด้วย isolation: "worktree" แล้วรวมทีหลัง ลดโอกาส conflict
  4. ห้าม flutter pub upgrade, ห้ามแก้ pubspec.yaml (ยกเว้น TASK-0.2), ห้ามแตะ .env, ห้าม bump version รายタスク
  5. bump version ครั้งเดียวตอนรวมงาน — งานนี้เป็น minor: 1.13.1+124 → 1.14.0+125
  6. เกณฑ์ส่งงาน — flutter analyze ไม่มี error ใหม่ และ flutter test ผ่านครบ 34 ไฟล์ ก่อนบอกว่าเสร็จ
  7. รายงานเป็นภาษาไทย พร้อมรายการไฟล์ที่แก้ และจุดที่ตัดสินใจเองเพราะ artboard ไม่ได้ระบุ
  8. งานที่กระทบโค้ดต้องผ่าน code_reviewer ก่อนปิด (Wave 3)

6ยุทธศาสตร์โหมดมืด

ยืนยัน: ต้องรองรับโหมดมืดเต็มรูปแบบ การที่แคนวาสล็อกไว้ที่โหมดสว่าง เป็นเพราะอยากรีวิวทีละโหมดเท่านั้น ชุดสีมืดมีครบอยู่แล้วใต้ :root[data-theme="dark"] ของทุก artboard

  1. main.dart คง themeMode: ThemeMode.system ไว้เหมือนเดิม ไม่แตะ
  2. ทุกค่าสีต้องผ่าน JdcColors เท่านั้น เพราะ extension จะสลับค่าตามธีมให้เอง — ถ้าเห็น Colors.white ที่ไหนแปลว่ายังไม่เสร็จ
  3. สีที่ ไม่กลับทิศ ระหว่าง 2 โหมด (เช่น green-fill, green-dot) ให้คงค่าเดิมทั้งคู่ ตามที่แคนวาสทำไว้
