ฝากซื้อ S8–S9 — เส้นทางแตก, คิวแอดมิน, ปิดงาน

v1 · 2026-09-23 · ต่อจากแผนหลัก Plan/Shop_Errand_Service_Feature_Plan_v4.html หัวข้อ 9 · S7 (AI อ่านบิล) ข้ามไปก่อนตามที่ผู้ใช้สั่ง

1. สิ่งที่มีอยู่แล้ว (S3–S6)

  • ยกเลิกได้ทุกสถานะ: ก่อนถึงร้านคืนเต็ม · ตอน shopping ลูกค้ายกเลิกหัก 25% สูงสุด 100฿ เข้าคนขับ · หลังจ่ายที่ร้านแล้วแอดมินเท่านั้น และกันค่าสินค้าคืนคนขับ
  • ของหมด: คนขับติ๊ก unavailable รายชิ้นได้ · ไม่ได้ซื้ออะไรเลย = ปิดยอดไม่ได้ (nothing_bought)
  • เกินวงเงิน: shop_mark_purchased ปฏิเสธด้วย exceeds_hold — แต่ยังไม่มีทางให้ลูกค้าเพิ่มวงเงิน คนขับติดตัน
  • ธงให้แอดมินดู: amount_variance, arrival_self_reported, cancelled_after_purchase — แต่ยังไม่มีหน้าให้แอดมินดู
  • config พร้อมแล้ว: shop_match_timeout_min=10, shop_photo_confirm_min=5, shop_photo_escalate_min=20

2. งาน S8

#เส้นทางทำอย่างไรที่
1หาคนขับไม่ได้cron ทุกนาที: pending ไม่มีคนขับนานเกิน shop_match_timeout_min → ยกเลิก + คืน hold เต็มจำนวน + แจ้งลูกค้าDB
2เกินวงเงินคนขับกด "ขอให้ลูกค้าเพิ่มวงเงิน" → server คำนวณยอดที่ขาดเอง → ลูกค้าเห็นแถบบนหน้าติดตาม กด "เพิ่มวงเงิน ฿X" (กันเงินเพิ่มจาก Wallet) หรือ "ไม่เพิ่ม" (คนขับตัดรายการ) · เงินไม่พอ → ไปหน้าเติมเงินDB + แอปทั้งสองฝั่ง
3ลูกค้าไม่ยืนยันรูปcron: receipt_review เกิน shop_photo_escalate_min → ธง customer_no_confirm + แจ้งแอดมิน (แอดมินยืนยันแทนได้อยู่แล้ว) · ไม่มี auto-confirm ตามข้อกำหนดเดิมDB
4ของหมดทั้งหมดไม่ต้องทำเพิ่ม — คนขับยกเลิกได้โดยลูกค้าได้เงินคืนเต็ม (ไม่มีค่าปรับเพราะไม่ใช่ลูกค้ายกเลิก)—
5AI ล่มข้าม — ไม่มี AI จนกว่าจะทำ S7—
6แจ้งเตือนtrigger สถานะออเดอร์ฝากซื้อ → แจ้งในแอปลูกค้า/คนขับ · ธง needs_admin_review ขึ้น → แจ้งแอดมิน (กระดิ่ง admin-web)DB
7คิวแอดมินหน้า admin-web ใหม่ "ออเดอร์ฝากซื้อ": แท็บต้องตรวจสอบ / ทั้งหมด · ดูรายการ รูปหลักฐาน เหตุผลธง · ปุ่ม ยืนยันรูปแทนลูกค้า · ปิดงาน · ยกเลิก+คืนเงิน · ทำเครื่องหมายตรวจแล้ว (พร้อมโน้ต)DB + admin-web
8รายงานคนขับผิดปกติแท็บ "คนขับ": จำนวนงาน / สำเร็จ / ถูกยกเลิกตอนซื้อของ (มีค่าปรับ) / ยืนยันถึงร้านเอง · เรียงตามอัตรายกเลิก · สลับ trusted ได้ในหน้าเดียว (ใช้ใน S9)DB + admin-web

3. งาน S9

  • code_reviewer ตรวจงาน S8 ทั้งหมด แก้จนผ่าน
  • bump version แอป + admin-web แล้ว commit แยกไฟล์จากงาน Wave 1.5 ของ Codex
  • deploy migration + admin-web (ขออนุมัติก่อน)
  • ร้านมีแล้ว 40 ร้าน · shop_enabled=true อยู่แล้ว
  • ตั้งคนขับ trusted: ต้องให้แอดมิน/ผู้ใช้เลือกเองว่าคนขับคนไหน — ทำได้จากแท็บ "คนขับ" ในหน้าใหม่ (ผมจะไม่เลือกให้เอง)
  • merge เข้า main และ push: รอคำสั่งผู้ใช้

4. หลักการที่ต้องคงไว้

  • เงินทุกบาทคำนวณที่ server — ยอดที่ขาดตอนเกินวงเงินคำนวณจาก snapshot ของออเดอร์ ไม่รับตัวเลขจากแอป
  • ทุกการเคลื่อนเงินอยู่ใน transaction เดียว + ลง ledger (hold/refund) ทุกครั้ง
  • cron ใช้ FOR UPDATE SKIP LOCKED กันชนกับคนขับที่กดรับงานพอดี
  • ทดสอบบน production แบบ transaction + ROLLBACK (ต้องได้อนุมัติ) — ไม่มีข้อมูลค้าง
