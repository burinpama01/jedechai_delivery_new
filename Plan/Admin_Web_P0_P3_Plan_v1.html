2. P1a — Laundry: admin จัดการแทนร้านครบชุด

ปัจจุบันหน้า Laundry (admin-web/src/pages/laundryPage.js) ทำได้แค่ ดูรายการ/จัดการแพ็กเกจ/assign คนขับ — RPC ฝั่งร้าน (merchant_send_laundry_quote, merchant_update_laundry_status, create_laundry_return_booking) เช็ค auth.uid() = merchant/customer ทำให้ admin เรียกตรงไม่ได้

2.1 Migration ใหม่ (deploy ผ่าน node+pg เท่านั้น — ดูหัวข้อ 6)

  • สร้าง admin-variant DB functions (SECURITY DEFINER, GRANT EXECUTE เฉพาะ service_role — ห้าม grant ให้ authenticated):
    • admin_send_laundry_quote(p_laundry_order_id, p_laundry_amount, p_delivery_fee_outbound, p_quote_message, p_quote_expires_minutes, p_platform_gp_rate) — นำ logic จาก merchant_send_laundry_quote (เวอร์ชันล่าสุดใน migration 20260702160000_laundry_cancel_refund_and_stage_fixes.sql) มาใช้โดยตัดเช็ค merchant_id ออก อย่า duplicate สูตร GP — ถ้าแยก shared function ได้ให้แยก ถ้าเสี่ยงให้ copy แล้ว comment อ้างที่มา
    • admin_update_laundry_status(p_laundry_order_id, p_status) — stage guard เดียวกับของ merchant (washing เมื่อ at_merchant; completed เมื่อ self_pickup + ready_for_return) แต่ไม่เช็ค merchant_id
    • admin_cancel_laundry_order(p_laundry_order_id, p_reason, p_do_refund) — ยกเลิกได้ทุกสถานะที่ไม่ใช่ completed/cancelled:
      • สถานะก่อนชำระ (quote_requested/quoted/quote_expired/quote_rejected): เปลี่ยนสถานะ + notify
      • สถานะหลัง accept: ถ้ามี booking ค้าง (outbound/return) ให้ยกเลิก booking ด้วย logic เดิม (admin_force_cancel_booking_with_wallet_refund / cancel_wallet_booking_with_refund จาก migration 20260702160000) แล้ว sync laundry_orders เป็น cancelled; ถ้าจ่าย wallet แล้วและ p_do_refund=true ให้คืนเงินตามแนวทาง refund เดิม (refund_booking_to_customer_wallet) — ตรวจ flow การ hold/charge จริงใน migration ก่อนเขียน ห้ามเดา
  • ตรวจ constraint ของ laundry_quote_messages.sender_role — ถ้าจำกัดแค่ customer/merchant ให้ขยายรองรับ admin

3. P1b — Cache busting

  • แก้ scripts/prepare-admin-web-netlify-deploy.mjs: ตอน copy ให้ stamp ?v=<version จาก admin-web/package.json>-<timestamp> ลง index.html (ทั้ง src/main.js และ app.js) และ sync ASSET_VERSION ใน app.js อัตโนมัติ — แก้เฉพาะใน out dir ไม่แตะ source
  • เพิ่ม Cache-Control ใน admin-web/_headers: /index.html + / → no-cache; ไฟล์ *.js → public, max-age=300, must-revalidate (ยังไม่มี content-hash จึงใช้ max-age สั้น)
  • ห้ามลบ clear-cache.html (อยู่ในรายการรอลบ)

5. P3 — งานเพิ่ม (additive เท่านั้น)

  • Migrate หน้า Settings: ย้าย renderSettings + ส่วน banners/assets/GP/system config จาก app.legacy.js มาเป็น implementation เต็มใน src/pages/settingsPage.js (แนวเดียวกับหน้าที่ย้ายแล้ว เช่น driversPage) — ห้ามลบโค้ดฝั่ง legacy แค่ทำให้ src ถูกใช้ก่อนผ่าน bridge เดิม; escape ทุกค่า DB ด้วย escapeHtml ปิดช่อง XSS ที่ audit เก่าเจอ
  • หน้า Reviews: หน้าใหม่ reviewsPage.js + sidebar "รีวิว" — list รีวิวล่าสุด (ตาราง: ผู้ให้, ผู้ถูกรีวิว, ดาว, คอมเมนต์, วันที่, order) + action ซ่อน/ลบรีวิวไม่เหมาะสมผ่าน admin-actions ใหม่ (admin_delete_review หรือ soft-hide ตาม schema จริง — ตรวจตาราง reviews ใน migrations ก่อน)
  • Broadcast: UI ส่งประกาศ (อยู่ในหน้า Settings หรือหน้าใหม่): เลือกกลุ่มเป้าหมาย (ทุกคน/ลูกค้า/คนขับ/ร้าน), หัวข้อ+ข้อความ → action admin_broadcast_notification ใน admin-actions: insert notifications เป็น batch + ยิง FCM ผ่าน function send-fcm-notification ที่มีอยู่ (ตรวจ signature การเรียกก่อน) — จำกัด batch size ป้องกัน timeout
  • อัปเดต sidebar ใน index.html + src/router/meta.js (page titles) + src/pages/index.js ให้ครบทุกหน้าใหม่

6. Deploy (ยืนยันวิธีจาก deployment.md แล้ว)

  1. Migrations: ห้าม supabase db push (history desync) — ใช้ node+pg ต่อ DB ตรงด้วย SUPABASE_DATABASE_URL จาก .env (host aws-1-ap-south-1) ตาม pattern ใน deployment.md ของ Obsidian; รัน guard test query หลัง apply
  2. Edge function: deploy admin-actions ตามวิธีที่เคยสำเร็จใน deployment.md; smoke test: เรียกโดยไม่มี JWT ต้องได้ 401
  3. Admin-web: node scripts/prepare-admin-web-netlify-deploy.mjs → deploy โฟลเดอร์ out ขึ้น Netlify site jedechai-delivery ตามวิธีใน deployment.md → เปิด production URL ตรวจ HTTP 200 + version stamp ใหม่
  4. บันทึก deploy id + ผล verify ลง deployment.md
