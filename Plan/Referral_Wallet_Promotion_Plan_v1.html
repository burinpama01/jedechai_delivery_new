📜 ความต้องการของผู้ใช้ (บันทึกตรงตัว):
  1. คนขับ ชวนร้านค้าเปิดร้าน → อนุมัติสำเร็จ → คนขับรับ wallet
  2. ลูกค้า ชวนร้านค้าเปิดร้าน → อนุมัติสำเร็จ → ลูกค้ารับ wallet
  3. คนขับ ชวนคนขับ → รับออเดอร์แรกสำเร็จ (completed) → คนขับทั้งสองฝั่งรับ wallet
  4. Wallet แยกชัดเจน: เงินจากการเติม / เงินจากระบบ (โปรโมชั่น/รางวัล) — แสดงยอดรวมเดียว
  5. ถอนได้ ขั้นต่ำ ฿200

2) การออกแบบหลัก

2.1 ถังเงิน 2 ใบ ในกระเป๋าเดียว

wallets: balance (ยอดรวม — คงเดิม ใช้แสดงผล/ใช้จ่าย) + balance_withdrawable (ถัง "จากระบบ" — แหล่งเดียวที่ถอนได้) ← คอลัมน์ใหม่ การเติมเข้าถังไหน — กำหนดด้วย type ของ ledger: เข้าถังเติม (ไม่ถอนได้): topup, refund เข้าถังระบบ (ถอนได้): referral_reward, coupon_compensation, laundry_payout, job_payout, admin_adjustment(เฉพาะที่แอดมินกดให้เป็นรางวัล) การใช้จ่าย (จ่ายออเดอร์/ค่าคอมมิชชัน): หักจาก balance รวม โดยหักถังเติมก่อน → ถังระบบถูกสะสมไว้ให้ถอน (กติกาแนะนำ — ดูคำถามเปิด ข้อ 2) การถอน: wallet_deduct แบบ withdrawable-only — ถ้าถังระบบ < 200 = ปุ่มถอน disabled ขั้นต่ำมาจาก system_config (withdrawal_min_amount = 200) — แอดมินแก้ได้

2.2 สามสถานการณ์รางวัล (S1/S2/S3)

สถานการณ์เงื่อนไขจ่ายผู้รับทริกเกอร์ (server-side ทั้งหมด)
S1 คนขับชวนร้านร้านสมัครด้วยโค้ด → แอดมินอนุมัติ (approval_status → approved)คนขับผู้ชวนAFTER UPDATE ON profiles (role=merchant, อนุมัติสำเร็จ) + referrals(scenario=merchant_signup)
S2 ลูกค้าชวนร้านเหมือน S1ลูกค้าผู้ชวนtrigger เดียวกับ S1 (ตรวจ role ของ referrer ตอนจ่าย: driver หรือ customer)
S3 คนขับชวนคนขับคนขับใหม่สมัครด้วยโค้ด → ออเดอร์แรก completed (driver รับงานและจบงานสำเร็จ)ทั้งสองฝั่ง (ผู้ชวน + คนขับใหม่)ขยาย trigger เดิมบน bookings (ตรวจ: referee เป็น driver + เป็น completed แรกของเขา)

2.3 กลไกกันโกง/กันจ่ายซ้ำ

  • Idempotency: unique (referral_id, beneficiary_user_id, reward_type) บน referral_rewards — trigger เช็คก่อนจ่ายทุกครั้ง จ่ายจริงครั้งเดียว
  • เงื่อนไข role ตอนจ่าย: S1/S2 referrer ต้องยังเป็น driver/customer ตามสถานการณ์ ณ วันที่อนุมัติร้าน
  • ไม่นับตัวเอง: referrer ≠ referee
  • แคปรายผู้ชวน: system_config เช่น referral_max_rewards_per_month (แนะนำ 20) — เกินเก็บ status='pending_review' ให้แอดมินกดอนุมัติเอง
  • S3 นับเฉพาะออเดอร์แรกจริง: ใช้ "completed ครั้งแรกของ referee ในฐานะ driver" — ตรวจจาก bookings ที่ driver_id=referee สถานะ completed เรียงตามเวลา
  • รายงานแอดมิน: หน้า admin-web "Referral payouts" — รายการจ่ายทั้งหมด/ค้างอนุมัติ/สรุปต่อผู้ใช้ (กันการรีวิวย้อนหลังยาก)

3) งานตามลำดับ (Phases)

Phase 0 — สิ่งที่ต้องทำก่อน (จากรายงานวิเคราะห์ Wallet — เงินจริงจะเข้าระบบแล้ว)

  • P0-1 (W2): DROP policy เขียนตรงบน wallets/wallet_transactions — ปิดประตูตั้งยอดเอง (แอปไม่ใช้ทางนี้ ตรวจแล้ว) · ต้องทำ
  • P0-2 (W4): ย้อนเงินทดสอบ admin_adjustment +฿977,620 ด้วยรายการ reverse ที่อธิบายเหตุผล — ถ้าไม่ทำก่อนตั้งค่าถัง ฿1 ล้านจะกลายเป็น "ถอนได้" ทันที · ต้องทำ
  • P0-3 (W3): ซ่อม 3 กระเป๋าที่ balance≠ledger (−100/+100/+276.05) ด้วยรายการปรับที่มี description — ให้ baseline ตั้งถังสะอาด · ควรทำ
  • P0-4 (W5): E2E flow ถอนเดิม 1 รอบ (ขอ→อนุมัติ→เดบิตจริง) ก่อนเปิดใช้จริง · ควรทำ

Phase 1 — Migration ฐานข้อมูล (1 ไฟล์ + script baseline)

  • wallets.balance_withdrawable (numeric, default 0) + script ตั้งค่าเริ่มต้นจากการจัดประเภท ledger ทั้งหมดตามกติกา 2.1 (หลัง P0-2/P0-3 เท่านั้น)
  • RPC wallet_topup/wallet_deduct: เพิ่ม logic ถัง — topup แยกถังตาม type; การใช้จ่ายหักถังเติมก่อน; เพิ่ม RPC wallet_deduct_withdrawable สำหรับถอน (ตรวจยอดถังระบบพอ + ไม่ให้ติดลบ)
  • referrals.scenario (text) + backfill ข้อมูลเดิมเป็น customer_invite + unique constraint บน referral_rewards
  • system_config: withdrawal_min_amount=200, referral_reward_driver_invite_merchant=?, referral_reward_customer_invite_merchant=?, referral_reward_driver_invite_driver_referrer=?, referral_reward_driver_invite_driver_newdriver=?, referral_max_rewards_per_month=20 (ค่าตัวเลข = คำถามเปิดข้อ 1)
  • RPC apply_referral_code(p_user_id, p_code): ผูกโค้ดตอนสมัคร/เติมโปรไฟล์ — ตรวจ role คร่าวๆ ตอนผูก และเข้มงวดอีกครั้งตอนจ่าย + กันผูกซ้ำ/ผูกตัวเอง
  • Trigger จ่ายเงิน 2 ตัว (S1/S2 บน profiles + S3 ขยายตัวเดิมบน bookings): จ่ายผ่าน wallet_topup(type='referral_reward') + INSERT referral_rewards + แจ้งเตือนผู้รับ ("ได้รับเงินรางวัล ฿XX จากการชวน…") — ทั้งหมดในธุรกรรมเดียว idempotent

Phase 2 — แอป (Flutter)

  • ฝั่งผู้ชวน (ทุก role): หน้าแชร์โค้ด (มีอยู่บางส่วน) — โค้ด + ปุ่มคัดลอก/แชร์ + อธิบายกติกา 3 สถานการณ์ + ยอดรางวัลที่เคยได้
  • ฝั่งผู้ถูกชวน: ช่อง "โค้ดผู้ชวน" ในขั้นสมัคร/เติมโปรไฟล์ (merchant onboarding ขั้น 1 ที่เพิ่งปล่อย + สมัคร driver) — v1 ใช้ฟิลด์กรอก (deep link เป็น v2)
  • Wallet screen: แสดง ยอดรวม (ใหญ่) + แยกย่อย 2 ถัง (เติม/ระบบ) + ปุ่มถอน — disabled พร้อมข้อความ "ถอนได้จากยอดรางวัล ขั้นต่ำ ฿200" เมื่อถังระบบ < 200
  • แจ้งเตือน: type ใหม่ referral_reward — แตะแล้วพาไปหน้า wallet/ประวัติ

Phase 3 — Admin-web

  • หน้า "Referral payouts": ตารางจ่ายทั้งหมด + ค้าง review (เกินแคป) + ปุ่มอนุมัติ manual + สรุปรายเดือนต่อผู้ใช้
  • Settings: แก้ได้ทุกค่า system_config ข้างต้น (จำนวนเงิน/แคป/ขั้นต่ำถอน)
  • หน้าถอนเดิม: ผูกกติกาใหม่ (โชว์ถังระบบของผู้ขอ)

4) แผนทดสอบ (TDD) + E2E

  • Smoke/unit เขียนก่อน: migration markers (ถัง/scenario/unique/RPC ถอน), RPC logic (หักถังเติมก่อน, ถอนเกินถังระบบ = ปฏิเสธ, ต่ำกว่า 200 = ปฏิเสธ)
  • E2E rollback (แพทเทิร์นเดียวกับ 19 ก.ย.): จำลองใน transaction ที่ rollback — (1) สมัคร merchant ด้วยโค้ดคนขับ → อนุมัติ → เช็ค wallet +referral_reward + notification + rewards row (2) ทำซ้ำ → ต้องไม่จ่ายซ้ำ (unique) (3) สมัคร driver ด้วยโค้ด → complete ออเดอร์แรก → ทั้งสองกระเป๋า +เงิน (4) ถอน 150 → ปฏิเสธ / ถอน 250 จากถังระบบ 100 → ปฏิเสธ / ถังระบบ 300 → ผ่าน เดบิตเฉพาะถังระบบ (5) ใช้จ่ายจากกระเป๋าที่มี 2 ถัง → เดบิตถังเติมก่อน ถังระบบคงเดิม
  • ทดสอบจริงหลัง deploy: emulator ครบ 3 สถานการณ์ + แจ้งเตือน + หน้า wallet แสดง 2 ถัง + แอดมินเห็นในหน้า payouts

5) ลำดับ deploy + rollback

  • Phase 0 → migration Phase 1 → admin-web → แอป (แอดมินก่อนเพื่อตั้งค่าเงินรางวัล แล้วค่อยเปิดแอปแชร์โค้ด)
  • Rollback: ทุกฟังก์ชัน CREATE OR REPLACE (เก็บ def เดิมใน comment); ถังใหม่เป็น additive — ปิดกั้นการจ่ายได้ด้วยการตั้ง referral_max=0 ใน config โดยไม่ต้อง rollback โค้ด
  • เงินที่จ่ายไปแล้ว: ไม่ย้อนอัตโนมัติ — มีรายงานครบไว้ตรวจทาน

6) คำถามเปิดที่ต้องการคำตอบก่อน implement

  1. จำนวนเงินรางวัล: S1 คนขับชวนร้าน = ฿___ · S2 ลูกค้าชวนร้าน = ฿___ · S3 ผู้ชวน = ฿___ + คนขับใหม่ = ฿___ (แนะนำช่วงเริ่ม: ร้าน 100–200 / คนขับ 50+50 ทดสอบก่อนขยาย)
  2. กติกาหักถังเวลาใช้จ่าย: แนะนำ "หักถังเติมก่อน เก็บถังระบบไว้ถอน" — ตกลงตามนี้ไหม หรือต้องการเผาถังระบบก่อน?
  3. ยืนยัน: ถอนได้จาก "ถังระบบ" เท่านั้น (เงินที่ลูกค้าเติมเองถอนคืนไม่ได้ — ใช้จ่ายในแอปอย่างเดียว) ใช่ไหม? (แนะนำใช่ — กันช่องทางฟอกเงิน/รีฟันด์นอกระบบ)
  4. แคปรายผู้ชวน: เดือนละกี่รางวัลก่อนเข้าโหมดแอดมินอนุมัติ? (แนะนำ 20)
  5. การถอนของจริง: ใช้ flow แอดมินอนุมัติ手动 (โอนเองแล้วกดอนุมัติ) ตามระบบเดิมใช่ไหม หรือต้องผูกพร้อมเพย์อัตโนมัติใน v1? (แนะนำแอดมินอนุมัติก่อน)
