📜 บันทึกการตัดสินใจของผู้ใช้ (19 ก.ย. — ตอบคำถามเปิ่าทั้ง 5 ข้อของ v1):
  1. จำนวนเงินรางวัล: แอดมินตั้งค่าได้ทุกตัว · ค่าเริ่มต้น ฿20 ต่อรางวัล
  2. การใช้จ่าย: หักถังระบบก่อน (เงินระบบแจกถูกใช้ก่อน คงเงินที่ผู้ใช้เติมเองไว้ทีหลัง)
  3. การถอน: เติมเองก็ถอนได้ ขั้นต่ำ ฿100 · ถังระบบ (รางวัล) ถอนได้ขั้นต่ำ ฿200 (ตาม requirement เดิม)
  4. ระบบขั้นบันได: ทำ — ผู้ชวนยิ่งสำเร็จมาก ยิ่งรับรางวัลต่อรายสูงขึ้น
  5. การถอนจริง: แอดมินอนุมัติ manual เท่านั้น (ไม่ผูกพร้อมเพย์อัตโนมัติใน v1)

1) สรุปสิ่งที่เปลี่ยนจาก v1

หัวข้อv1v2 (ตามคำตัดสินใจ)
จำนวนเงินรางวัลคำถามเปิดแอดมินตั้งได้ · default ฿20 ทุกตัว · + คูณด้วยขั้นบันได
ลำดับหักเงินตอนใช้จ่ายแนะนำหักถังเติมก่อนหักถังระบบก่อน → ที่เหลือจากถังเติม
การถอนเฉพาะถังระบบ (min 200)ถอนได้ทั้งสองถัง: ถังเติม min ฿100 · ถังระบบ min ฿200 (แอดมินแก้ได้)
ขั้นบันไดรางวัลไม่มีเพิ่มใหม่ — รางวัลต่อรายขยับตามจำนวนชวนสำเร็จสะสม
การอนุมัติถอนคำถามเปิดManual ผ่าน admin-web เท่านั้น + กลไก hold เงินระหว่างรออนุมัติ

2) การออกแบบที่อัปเดต

2.1 ถังเงิน + กติกาหัก/ถอน (แก้ไขจาก v1)

wallets: balance (ยอดรวม — เดิม) + balance_system (ถัง "จากระบบ" — คอลัมน์ใหม่) ถังเติม = balance − balance_system (computed ไม่ต้องมีคอลัมน์) เติมเข้าถังไหน (ตาม type ของ ledger): ถังเติม: topup, refund ถังระบบ: referral_reward, coupon_compensation, laundry_payout, job_payout, admin_adjustment (เมื่อแอดมินกดให้เป็นรางวัล) ใช้จ่าย (จ่ายออเดอร์/ค่าคอมมิชชัน): หัก balance_system ก่อน → ส่วนที่เหลือหักจากถังเติม (ตามคำตัดสินใจข้อ 2 "หักระบบก่อน") ถอน (แอดมินอนุมัติ manual เท่านั้น): ผู้ใช้เลือกถังที่จะถอน → ระบบ hold เงินทันที (withdrawal_hold) · ถังเติม: min ฿100 (withdrawal_min_topup) · ถังระบบ: min ฿200 (withdrawal_min_system) แอดมินอนุมัติ → hold แปลงเป็น deduction จริง (withdrawal_paid) แอดมินปฏิเสธ → คืนเงิน (withdrawal_release) + แจ้งเตือน ⇒ ระหว่างรออนุมัติเงินถูกล็อก กันใช้จายไปก่อนแล้วยอดไม่พอตอนโอน

2.4 สถานการณ์จ่ายเงิน (คงเดิมจาก v1)

สถานการณ์เงื่อนไขจ่ายผู้รับ + จำนวน
S1 คนขับชวนร้านร้านสมัครด้วยโค้ด → แอดมินอนุมัติ (profiles.approval_status → approved)คนขับผู้ชวน = ฐาน × ขั้นบันไดของเขา
S2 ลูกค้าชวนร้านเหมือน S1ลูกค้าผู้ชวน = ฐาน × ขั้นบันไดของเขา
S3 คนขับชวนคนขับคนขับใหม่สมัครด้วยโค้ด → ออเดอร์แรกในฐานะ driver completedผู้ชวน = ฐาน × ขั้นบันได + คนขับใหม่ = ฐานตรง

กันโกง/กันจ่ายซ้ำ (คงเดิม): unique (referral_id, beneficiary, reward_type) · ตรวจ role ตอนจ่าย · referrer ≠ referee · เกินแคป → status pending_review ให้แอดมินกด · S3 นับเฉพาะ completed แรกจริง · ทุกการจ่าย + แจ้งเตือน "🎉 ได้รับเงินรางวัล ฿XX จากการชวน…"

3) งานตามลำดับ (อัปเดต)

Phase 0 — ต้องทำก่อนเปิดโปรโมชั่น (คงเดิมจาก v1 — สรุป)

  • P0-1 (W2): DROP policy เขียนตรงบน wallets/wallet_transactions ต้องทำ
  • P0-2 (W4): ย้อนเงินทดสอบ admin_adjustment +฿977,620 — ถ้าไม่ทำ ฿1 ล้านจะกลายเป็นถังระบบ "ถอนได้" ทันที ต้องทำ
  • P0-3 (W3): ซ่อม 3 กระเป๋า balance≠ledger ก่อนตั้งค่าถังเริ่มต้น ควรทำ
  • P0-4 (W5): E2E flow ถอนเดิม 1 รอบ ควรทำ

Phase 1 — Migration (รวบเป็น 1–2 ไฟล์)

  • wallets.balance_system + script ตั้งค่าเริ่มต้นจากการจัดประเภท ledger (หลัง P0-2/P0-3)
  • RPC wallet: wallet_topup แยกถังตาม type · wallet_deduct หักระบบก่อน · ใหม่: wallet_withdraw_request(user, amount, source_bucket) — ตรวจขั้นต่ำตามถัง + hold เงินทันที · admin_withdraw_decide(request_id, approve/reject) — แปลง hold เป็น paid หรือคืนเงิน (service_role เท่านั้น)
  • referrals.scenario + backfill + unique บน referral_rewards (เพิ่มคอลัมน์ tier/amount ที่ใช้จ่ายจริง)
  • system_config ทั้ง 8 คีย์ตามตาราง 2.3 + RPC apply_referral_code
  • Trigger จ่าย S1/S2 (บน profiles ตอนอนุมัติร้าน) + S3 (ขยายบน bookings) — คำนวณขั้นบันไดตอนจ่าย + idempotent + แจ้งเตือน

Phase 2 — แอป (Flutter)

  • หน้าแชร์โค้ด (ทุก role): โค้ด + กติกา 3 สถานการณ์ + ขั้นบันไดปัจจุบัน + "อีก X รายถึงขั้นถัดไป" + ตารางขั้น + ประวัติรางวัลที่ได้รับ
  • สมัคร/เติมโปรไฟล์ (merchant ขั้น 1 + driver): ช่อง "โค้ดผู้ชวน"
  • Wallet screen: ยอดรวมใหญ่ + แยก 2 ถัง + ปุ่มถอนต่อถัง (เลือกถัง → ขั้นต่ำต่างกัน 100/200) + สถานะคำขอถอน (รออนุมัติ/สำเร็จ/ถูกปฏิเสธ)
  • แจ้งเตือน: referral_reward / withdrawal_result (อนุมัติ/ปฏิเสธ)

Phase 3 — Admin-web

  • หน้า "Referral payouts": จ่ายแล้ว/ค้าง review (เกินแคป)/สรุปรายผู้ชวน + ขั้นบันไดปัจจุบันของแต่ละคน
  • Settings: แก้ได้ครบ — ฐานรางวัล 4 ตัว / ขั้นบันได / แคป / ขั้นต่ำถอน 2 ถัง
  • หน้าถอน (เดิม เสริม): โชว์ถังต้นทาง + ยอดคงเหลือแยกถังของผู้ขอ + ปุ่มอนุมัติ/ปฏิเสธ (manual เท่านั้น)

4) แผนทดสอบ (อัปเดตตามกติกาใหม่)

  • Unit/smoke: marker migration ทั้งหมด + กติกา RPC (หักระบบก่อน / hold ตอนขอถอน / ขั้นต่ำตามถัง / คำนวณขั้นบันไดถูกช่วง)
  • E2E rollback (แพทเทิร์น 19 ก.ย.): (1) S1 จ่าย ฿20 ขั้น 1 → ผู้ชวนชนะรายที่ 6 → จ่าย ฿25 ขั้น 2 ✓ (2) จ่ายซ้ำ = ไม่จ่าย · (3) S3 จ่ายสองกระเป๋า (ผู้ชวน ×ขั้น + คนใหม่ตรง) (4) ถอนถังเติม 150 จากถัง 80 → ปฏิเสธ (ต่ำกว่า min 100 และยอดไม่พอ) · ถอนถังระบบ 150 → ปฏิเสธ (ต่ำกว่า 200) · ถอน 250 → hold สำเร็จ (5) อนุมัติ → paid / ปฏิเสธ → เงินคืน + แจ้งเตือน (6) ใช้จ่ายจากกระเป๋า 2 ถัง → หักถังระบบก่อน ถังเติมคงเดิม
  • ทดสอบจริงหลัง deploy: ครบ 3 สถานการณ์ + ขั้นบันไดขยับ + ถอน 2 ถัง + แอดมิน manual ครบวง

5) Deploy + Rollback (คงเดิม + เพิ่ม)

  • Phase 0 → migration → admin-web → แอป · RPC ทั้งหมด backward-compatible
  • ปิดกั้นการจ่ายชั่วคราวได้ตลอดเวลา: referral_max_rewards_per_month=0 (ไม่ต้อง rollback โค้ด)
  • Rollback: CREATE OR REPLACE กลับ (เก็บ def เดิมใน comment) · เงินที่จ่าย/ถอนแล้วมี audit ครบ ไม่ย้อนอัตโนมัติ
สถานะ: Planning — ตัดสินใจครบแล้ว ไม่มีคำถามเปิ่าคงเหลือ · พร้อมเริ่มได้ทันทีเมื่ออนุมัติ (แนะนำลำดับ: Phase 0 สั้นๆ ก่อน → migration) · จุดแก้ RPC wallet สามารถรวมกับแผนคูปอง (coupon_compensation) เป็น migration เดียวกันได้
