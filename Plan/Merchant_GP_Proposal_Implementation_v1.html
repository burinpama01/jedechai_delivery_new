เป้าหมายและสัญญาข้อมูล

ตาราง merchant_gp_proposals เก็บ merchant_id, revision, status (pending/returned/approved/superseded), gp_rate, base_delivery_fee, base_distance_km, per_km_charge, merchant_note, rejection_reason, reviewed_by, reviewed_at, created_at พร้อม profiles.gp_proposal_id และ gp_proposal_status ที่ server ควบคุม

RPC merchant_submit_gp_proposal รับตัวเลขและ note สร้างรอบใหม่เฉพาะร้านอาหารที่ยังไม่ approved RPC admin_review_gp_proposal รับ proposal id, decision, reason และ GP split ตอนอนุมัติ ล็อก profile ก่อน proposal ทุกกรณี

1. ทดสอบก่อนแก้

เพิ่ม profile_completion_policy_test ให้ pending/returned/approved proposal ไปดูสถานะได้ แต่ id/status ปลอมไม่ผ่าน และเพิ่มทดสอบ proposal validation, status rendering และ admin action ที่ไม่เปิดร้านข้ามข้อเสนอ

flutter test test/profile_completion_policy_test.dart

2. ฐานข้อมูล

สร้าง migration ใหม่ RLS อ่านเฉพาะ owner/admin ห้ามเขียนตารางตรง RPC ตรวจ role/type/numeric/เหตุผล/split/latest revision และการอนุมัติเป็น transaction เดียว Guard profile metadata กับ approval trigger ปิดทางข้ามทั้ง Admin Web และ Flutter การเลือกแพ็กเกจหลังตีกลับ supersede ข้อเสนอเดิมและล้าง metadata

3. Flutter

สร้าง service/model และฟอร์ม proposal ใช้ร่วมสมัครและเสนอใหม่ เพิ่มคำอธิบาย GP และค่าส่ง profile_completion_screen เลือก mode ได้ pending_approval_screen แสดงสถานะ รีเฟรช ประวัติและปุ่มเสนอใหม่ Admin Flutter เปิดหน้าพิจารณา proposal ได้

4. Admin Web และ Edge Function

เพิ่ม review action ผ่าน admin-actions ที่ตรวจ admin เดิม แสดงสถานะใน merchantsPage และเปิด review พร้อมประวัติ ตรวจ false success payload ก่อนแจ้งสำเร็จ การอนุมัติร้านต้องรับรองข้อเสนอผ่านแล้ว

5. ตรวจและปิดงาน
