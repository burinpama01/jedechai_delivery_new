ระบบเสนอออเดอร์ให้คนขับทีละคน

v1 · 26 กันยายน 2026 · สถานะ: อนุมัติพฤติกรรมหลักแล้ว, รอ implementation และ verification

เป้าหมายและภาพตัวอย่าง

เมื่อออเดอร์พร้อมหาคนขับ ให้เสนอแก่คนขับที่ว่างและใกล้จุดรับที่สุดหนึ่งรายนาน 60 วินาที คนขับกดรับหรือกดข้ามงานได้ หากกดข้าม ให้หยุดเสียงและเสนอรายถัดไปทันทีโดยไม่รอหมดเวลา; หากหมดเวลา ให้เสนอรายถัดไปเช่นกัน โดยไม่วนกลับหาคนเดิมในรอบนั้น

ทางเลือกที่พิจารณา

ทางเลือกผล
คิวฝั่ง server + transaction (เลือก)ทนการปิดแอป/หน้าแอดมิน และคุมการชนกันของหลายออเดอร์
จับเวลาในแอปหรือหน้าแอดมินทำง่ายกว่า แต่ timer หยุดหรือรีเซ็ตเมื่อปิดหน้า
มอบหมายทันทีเร็ว แต่คนขับไม่มีโอกาสรับหรือปฏิเสธ

ขอบเขตข้อมูลและสถานะ

  • ตารางข้อเสนอเก็บ booking, driver, เวลาเริ่ม/หมดอายุ, สถานะ offered/accepted/skipped/expired และเลขลำดับการเสนอ; มีข้อเสนอ active ได้หนึ่งรายการต่อ booking และหนึ่งรายการต่อ driver
  • จัดอันดับคนขับจากตำแหน่งและ heartbeat ที่ยังใหม่, online/available, ประเภทงานที่รับ, vehicle type, ไม่มีงาน active และไม่มีข้อเสนอ active; เรียงระยะใกล้ก่อนและมี tie-break ที่แน่นอน
  • หากไม่มีคนขับที่เหมาะสม งานคงสถานะรอและมีการ retry แบบ idempotent พร้อมสัญญาณให้แอดมินติดตาม
  • การรับงานตรวจ auth.uid(), ข้อเสนอที่ยัง active, เวลาหมดอายุ, booking ยังว่าง, capacity และเงื่อนไข wallet ที่ server ก่อนอัปเดตใน transaction เดียว

การแจ้งเตือน

ส่ง push เมื่อออกข้อเสนอและแสดงเวลา 60 วินาทีพร้อมปุ่ม “รับงาน” และ “ข้ามงาน” ในแอปคนขับ เมื่อแอปอยู่ด้านหน้าให้เล่นเสียงเตือนซ้ำจนกว่าจะรับ ข้าม หมดเวลา หรือข้อเสนอถูกยกเลิก เมื่อแอปอยู่เบื้องหลังให้ใช้ push มีเสียงตามข้อจำกัด Android/iOS; ไม่รับประกันเสียงวนต่อเนื่องเมื่อ OS ระงับแอป

การย้ายระบบและความปลอดภัย

ปิดตัวเลือกคนขับและ timer 120 วินาทีใน browser แอดมินหลัง worker ใหม่พร้อมใช้งาน แอดมินมอบหมายเองผ่าน RPC ที่ตรวจ expected state และ audit reason เท่านั้น จำกัดสิทธิ์อ่าน/เขียนข้อเสนอด้วย RLS/GRANT และคงงานที่กำลังดำเนินอยู่ไว้โดยไม่ย้ายคนขับอัตโนมัติ

เกณฑ์ตรวจรับ

  • ข้อเสนอหนึ่งงานไปทีละคน ครบ 60 วินาทีจึงเสนอรายถัดไปถ้าไม่มีคำตอบ; กดข้ามแล้วเสนอรายถัดไปทันที
  • หลายออเดอร์เข้าพร้อมกันไม่จองคนขับคนเดียวซ้ำเกิน capacity และไม่แย่งออเดอร์เดียวกัน
  • แอป/หน้าแอดมินปิดแล้วยังหมดเวลาและเดินคิวต่อได้
  • รับ/ข้าม/หมดเวลา หยุดเสียงและซ่อนข้อเสนอที่ใช้ไม่ได้
  • ผ่าน unit/integration concurrency test, static checks และ code review ก่อนขออนุมัติ migration/deploy แยกต่างหาก

ข้อจำกัดที่ต้องยืนยันด้วย runtime

ยังไม่ตรวจ production schema, FCM delivery และเสียงบนอุปกรณ์จริง จึงยังไม่อ้างว่า production พร้อมใช้งานจากผลทดสอบในเครื่อง
