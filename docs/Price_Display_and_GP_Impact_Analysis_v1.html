2) จุดที่ราคา "ไม่ตรงกันจริง" (display bug)

#จุดไม่ตรงต้นเหตุในโค้ดตัวอย่างที่เห็นต่างกันระดับ
P1ลูกค้ากับคนขับเห็นยอดรวมต่างกัน 1 บาท (ค่าส่งทศนิยม) ฝั่งลูกค้าใช้ .ceil() (ปัดขึ้นเสมอ) — customer_order_detail_screen, activity_screen / ฝั่งคนขับใช้ toStringAsFixed(0) (ปัดโดยธรรมชาติ) — driver_dashboard_screen ค่าส่ง ฿5.49 → ลูกค้าเห็นรวม ฿46 (ceil 45.49) แต่การ์ดงานคนขับโชว์ ฿45 แก้ง่าย-เห็นชัด

3) ความเสี่ยงด้าน GP (โครงสร้าง — กระทบเงินจริง)

G1 — GP ไม่ถูก snapshot ตอนสั่ง และ rate เปลี่ยนได้ตลอด พิสูจน์แล้วด้วยข้อมูลจริง

ออเดอร์ 8 ก.ย. (FD-F72643D1, อาหาร ฿79) settle ด้วย GP 5% / 20% (ระบบ 4 + คนขับ 16 = ฿20) แต่ config ปัจจุบันของร้านเดียวกันคือ 2% / 8% — เกิดจากร้านเปลี่ยนแพ็กเกจ GP ได้ตลอด (ฟีเจอร์ "เลือกแพ็กเกจ GP เอง" v1.10.0) และตัวเลข final คำนวณ ณ วันที่ complete ไม่ใช่วันที่สั่ง → ตัวเลขที่ลูกค้า/ร้านเห็นตอนสั่ง อาจไม่ใช่ตัวเงินที่จบงาน และไม่มี audit log การเปลี่ยน rate ให้ย้อนดูได้

G2 — ตัวเลข GP มาจาก "แอปคนขับคำนวณแล้วส่งมา" ไม่ใช่ server คำนวณเอง

complete_booking รับ p_driver_earnings/p_app_earnings จาก client แล้วบันทึกตรงๆ — ฝั่ง server มีฟังก์ชันคำนวณกลาง (connect_merchant_gp_amount) แต่ใช้เฉพาะ webhook StoreOS เท่านั้น ผลกระทบ: แอปคนขับเวอร์ชันเก่าที่ล็อกจิกเก่า/cache config เก่า หรือส่งเลขผิด → ระบบจ่ายตามเลขนั้น (ล่าสุดเคยแก้บั๊กส่ง price type ผิดใน webhook เดือน ก.ค. — ความเสี่ยงคลาสเดียวกัน)

G3 — คูปองระบบบนออเดอร์ "เงินสด": GP และยอดร้านคิดจากยอดเต็ม → คนขับรับภาระสด

โมเดลปัจจุบัน: GP = f(ยอดอาหารเต็ม) และร้านได้ = ยอดเต็ม − GP (ไม่หักคูปอง ถ้าไม่ใช่คูปองที่ร้านสร้างเอง) แต่คนขับเก็บเงินสดจากลูกค้าแบบหักคูปองแล้ว (driverCashToCollect = customerPayable) → ออเดอร์เงินสด + คูปองระบบ: คนขับเก็บ 35.79 แต่ต้องจ่ายร้าน 35 + โดนหักกระเป๋า 3 = ขาดทุนสด 2.21 ทันที (ยังไม่เคยเกิดจริงเพราะยังไม่มีออเดอร์ food ที่ใช้คูปองในระบบ — ตรวจแล้วทุกออเดอร์ล่าสุด coupon = null — แต่กลไกพร้อมพังทันทีที่มีคูปองระบบ + เงินสด)

G4 — คอลัมน์เงินสรุปครึ่งๆ กลางๆ ใน DB

total_amount, platform_gp_amount, merchant_net_amount = 0.00 ทุกออเดอร์ food (เติมเฉพาะ laundry) ตัวเลขจริงของ food อยู่ใน price+delivery_fee+driver_earnings+app_earnings → รายงาน/หน้า admin ที่อ่านคอลัมน์สรุปจะเห็น 0 (ต้องตรวจทุกจุดที่อ่าน 3 คอลัมน์นี้สำหรับ food)

5) ข้อเสนอแนะ (เรียงตามผลตอบแทน/ความเสี่ยง)

  1. แก้ P1 ทันที (เล็กมาก): unify การปัด — ทุกจอใช้ ceil ตัวเดียวกัน (หรือแสดงทศนิยม 2 ตำแหน่งทุกจอ) + เพิ่ม helper เดียวใน RoleAmountCalculator ให้ทุกฝั่งเรียก ไม่คำนวณเองแยก
  2. แก้ G2 (แนะนำอันดับ 2): ย้ายการคำนวณ GP เป็น server-side authoritative — complete_booking คำนวณจาก connect_merchant_gp_amount เอง (มีอยู่แล้ว!) แล้วเก็บ client ส่งมาเป็น audit เท่านั้น
